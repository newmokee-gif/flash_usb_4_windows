# WinUSB Creator — Windows и ГНУ/Линукс на USB

Приложение работает на Windows x64/ARM64, Linux x64/ARM64 и macOS Intel/Apple Silicon. При запуске появляется окно **«Вы будете устанавливать»** с вариантами **«Виндовс»** и **«ГНУ/Линукс»**. Это выбор системы для флешки, независимо от системы компьютера.

## Готовые приложения

Скачайте подходящий файл из [последнего релиза](https://github.com/newmokee-gif/flash_usb_4_windows/releases/latest).

| Компьютер | Формат |
| --- | --- |
| Windows Intel/AMD x64 | `WinUSB-Creator-Windows-x64.exe` |
| Windows 11 ARM64 | `WinUSB-Creator-Windows-ARM64.exe` |
| macOS 15+ Apple Silicon | `WinUSB-Creator-macOS-AppleSilicon.dmg` |
| macOS 15+ Intel | `WinUSB-Creator-macOS-Intel.dmg` |
| Debian x64/ARM64 | `flash-usb_0.3.1_all.deb` |
| Fedora x64/ARM64 | `flash-usb-0.3.1-1.noarch.rpm` |
| Debian/Fedora/Arch x64 | `flash-usb-v0.3.1-x86_64.AppImage` |
| Debian/Fedora ARM64 | `flash-usb-v0.3.1-aarch64.AppImage` |

Windows EXE автономный: отдельная папка `_internal` не нужна. Откройте DMG на Mac и перетащите приложение в «Программы». В AppImage включены Python/Tk; нужны glibc 2.36+ и графическая сессия. Выдайте файлу право запуска; если FUSE недоступен, используйте `--appimage-extract-and-run`.

DEB/RPM устанавливаются через `sudo apt install ./flash-usb_0.3.1_all.deb` или `sudo dnf install ./flash-usb-0.3.1-1.noarch.rpm`. Менеджер установит зависимости, включая aria2. Эти пакеты используют системный Python.

Контрольные суммы файлов — в `SHA256SUMS.txt`, сведения о сборке — в `RELEASE-PROVENANCE.json`. Исходники доступны по тегу релиза. GitHub сам добавляет ссылки Source code ZIP/tar.gz; скачивать их для запуска приложения не нужно.

## Режим «Виндовс»

Открывается привычный интерфейс Windows ISO → USB. На Windows доступны Windows 10 **x64 RU, x64 EN, x86 RU, x86 EN** и Windows 11 x64/ARM64 RU/EN. Архитектура ISO относится к целевому компьютеру. Официальная Windows 10 ARM64 ISO в каталог не добавлена.

Windows-версия сохраняет загрузчик ISO и torrent/magnet через aria2. Доступность автоматического получения Windows ISO зависит от Microsoft/Fido. Можно выбрать локальный ISO.

Linux/macOS-версии Windows-режима работают с локальным ISO, создают FAT32 для UEFI и разделяют большие WIM через wimlib. Legacy BIOS для этих режимов не заявляется. macOS использует MBR, Linux — GPT. Создание флешки на Apple Silicon не добавляет Mac возможность нативной загрузки Windows с USB.

## Режим «ГНУ/Линукс»

Выберите дистрибутив и доступную редакцию/архитектуру, затем скачайте образ. Каталог и официальные источники описаны в [docs/distro-sources.md](docs/distro-sources.md). ARM64 предлагается только для реально существующих установочных образов; поддержка платы или прошивки зависит от самого дистрибутива.

В текущих исходниках каталог расширен до **60 дистрибутивов и 77 вариантов образов**, включая 17 ARM64. Добавлены 30 разных систем, в том числе EndeavourOS, Artix, Garuda, MX Linux, Parrot OS, Solus, Tails, Puppy Linux, Rescuezilla и SystemRescue. Это расширение пока не входит в готовые приложения релиза v0.3.1.

Если есть официальный torrent, используется BitTorrent. В DMG и AppImage включён aria2, DEB/RPM устанавливают его как зависимость. В Windows Linux-режим при необходимости скачивает официальный aria2 с GitHub и проверяет закреплённые SHA-256 архива и EXE. На Windows 11 ARM64 при отсутствии нативного клиента отдельно запрашивается согласие на x64-помощник через эмуляцию ОС; само приложение остаётся нативным ARM64. При отсутствии торрента или ошибке загрузки программа сообщает о переходе на официальный HTTPS-сервер. Контрольная сумма из официального источника проверяется до разрешения записи. Для локального ISO/IMG укажите опубликованную разработчиком SHA-256.

Linux-образ записывается **целиком, побайтно**, вместе с таблицей разделов и загрузчиком, затем читается обратно и сравнивается. Файлы ISO не распаковываются на FAT32. Нужен пригодный для USB гибридный несжатый ISO/IMG; архивы и специальные образы плат не подменяются универсальными ISO.

Можно связать загрузку с последующей записью, но непосредственно перед стиранием требуется выбрать USB и подтвердить точный путь устройства. Изменение или подмена выбранного устройства блокирует запись.

**Все данные выбранной флешки будут удалены.** Системные и внутренние диски отклоняются; перед записью размонтируйте тома USB, не извлекая накопитель. ISO нельзя хранить на целевой флешке. Не отключайте устройство во время записи и проверки. После raw-записи Windows может предложить форматирование разделов Linux — не форматируйте установочную флешку.

## Зависимости

Для macOS Windows-режиму нужен внешний `wimlib`: `brew install wimlib`. При запуске из исходников установите также `aria2`. Кнопка «Установить Homebrew» открывает официальный интерактивный установщик в Терминале.

На Windows кнопка «Установить WinGet» получает официальный установщик с GitHub Microsoft и проверяет SHA-256 и подписи. Microsoft Store не используется. В прежнем Windows-режиме ARM64 для torrent/magnet нужен нативный aria2 ARM64 в PATH; это ограничение не относится к новому GNU/Linux-загрузчику, описанному выше. В Windows-режиме x64 прежний помощник aria2 может скачиваться автоматически.

Для Linux AppImage и запуска из исходников:

```sh
# Debian
sudo apt install python3 python3-tk util-linux mount parted dosfstools wimtools udev pkexec fonts-dejavu-core aria2
# Fedora
sudo dnf install python3 python3-tkinter util-linux parted dosfstools wimlib-utils systemd-udev polkit dejavu-sans-fonts aria2
# Arch
sudo pacman -Syu --needed python tk util-linux parted dosfstools wimlib systemd polkit ttf-dejavu aria2
```

Из исходников: `python3 flash_usb.py`; установка зависимостей — `python3 flash_usb.py install-deps` (Windows: `python`). Для GUI нужны Tk и графическая сессия; для повышения прав Linux — агент polkit. Homebrew/WinGet устанавливаются отдельно через соответствующие кнопки.

Windows EXE не подписаны Developer ID/Authenticode; macOS-приложения имеют ad-hoc подпись без нотариализации Apple. Для доверенного приложения на Mac используйте штатное «Открыть всё равно» после проверки контрольной суммы.

## Проверки

`python3 -m unittest discover -s tests -v` запускает проверки без записи физических накопителей. CI проверяет интерфейсы, архитектуры и самостоятельный запуск собранных приложений, Linux-пакеты и обе платформы ARM64. Дисковые тесты используют подставные команды и временные файлы.

Физическая запись и загрузка на целевом оборудовании остаются отдельной проверкой. Успешная сверка байтов не гарантирует совместимость прошивки, Secure Boot или драйверов конкретного компьютера. Архитектура компьютера, запускающего программу, и архитектура устанавливаемой системы могут различаться.
