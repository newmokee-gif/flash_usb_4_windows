# WinUSB Creator 0.2.0 — Windows, Linux and macOS

## Installation

**Windows x64:** download and run `WinUSB_Creator.exe`. This is the preserved original portable build, not a new Windows x64 rebuild.

**Windows 11 ARM64:** extract the complete ZIP and run `WinUSB-Creator-Windows-ARM64.exe`; keep `_internal` alongside it. Python/Tk are included. Automatic ISO downloading requires separately installed native ARM64 `aria2c`; local ISOs do not. The ZIP is not digitally signed.

**Debian / Fedora:** install the downloaded package; the package manager installs system dependencies:

```sh
# Debian
sudo apt install ./flash-usb_0.2.0.linux.2_all.deb
# Fedora
sudo dnf install ./flash-usb-0.2.0-0.2.linux.noarch.rpm
```

Open WinUSB Creator from the application menu or run `flash-usb`. DEB (`all`) and RPM (`noarch`) are ready-to-install Python application packages for both architectures, not standalone binaries.

**Linux AppImage:** Python/Tk are included; glibc 2.36+ and the documented system writing utilities are required. For ARM64, replace `x86_64` with `aarch64`:

```sh
chmod +x flash-usb-v0.2.0-linux.2-x86_64.AppImage
./flash-usb-v0.2.0-linux.2-x86_64.AppImage
# Without FUSE:
./flash-usb-v0.2.0-linux.2-x86_64.AppImage --appimage-extract-and-run
```

**macOS:** extract the ZIP, move the entire `WinUSB Creator.app` into Applications and run `brew install wimlib`. Python/Tk are included. Applications have ad-hoc signatures, not Developer ID signing or Apple notarization. If Gatekeeper blocks startup, verify SHA-256 and, for a trusted application, use Open Anyway in System Settings → Privacy & Security. Do not disable system protection globally.

## Verification and limitations

- Migrated files were checked against original SHA-256 hashes; new release assets were downloaded again and verified before switching publications.
- Previous checks covered Debian/Fedora/Arch, native ARM64 Debian/Fedora and Windows 11, and native macOS Intel/Apple Silicon. These include applicable GUI/CLI, architecture, packaging and WIM-operation tests. Windows x64 is a historical build; new ARM64 tests do not validate it.
- **Physical USB writing, target-hardware booting and interactive elevation dialogs have not been tested. Bug-free operation is not guaranteed.** Writing erases all data on the selected drive; back it up first.
- Linux and macOS create UEFI installation media; Legacy BIOS is not claimed. The macOS application does not install macOS or enable native Windows USB boot on Apple Silicon.
- 32-bit ARM is unsupported; Arch Linux ARM has not been tested. AppImage is not intended for musl/Alpine.

## Consolidated releases

This stable release replaces the public pages of `release` and `v0.2.0-linux.2`. They were converted to drafts; tags and original files are preserved. Prerelease filenames and internal package versions remain unchanged to preserve verified binaries. This consolidates publications rather than rebuilding every platform.

`RELEASE-PROVENANCE.json` records source releases, their notes, asset metadata and checksums. Original `SHA256SUMS-*` files referenced by ZIP instructions are also retained. The current source archive matches the new tag; exact historical sources for individual binaries are recorded in provenance where available. Windows/Linux ARM64 were built from `8c48d00b5de9cca5fa711433f87b8ddd674b17e8`; macOS from `fe57a83b2a2443fcdb1eb3e78ffc6186d40925f1`.

On Linux, verify downloaded files in a separate folder with `sha256sum --ignore-missing -c SHA256SUMS.txt`. On macOS, use `shasum -a 256 FILENAME`; on Windows, use `Get-FileHash .\FILENAME -Algorithm SHA256` and compare with `SHA256SUMS.txt`.
